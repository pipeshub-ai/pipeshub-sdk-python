# AGENTS.md

Python SDK for the PipesHub API, generated by [Speakeasy](https://www.speakeasy.com) from the OpenAPI spec. Most files here are generated: do not hand-edit them, because the next `speakeasy run` overwrites them.

## What you may edit

- `examples/`, `README.md`, `USAGE.md`: improve freely (README/USAGE sections between Speakeasy markers are regenerated, so keep edits outside them or re-apply after regeneration).
- `AGENTS.md`, `CLAUDE.md`, and every path in `.genignore` (Speakeasy does not overwrite those).
- `.genignore` currently pins the SSE event models in `src/pipeshub_sdk/models/*sseevent.py` (their `data` is `Any`) and their `docs/models/` pages. Keep a model and its doc page in sync.

## Regenerating

The spec lives in the sibling repo: `../pipeshub-ai/backend/nodejs/apps/src/modules/api-docs/pipeshub-openapi.yaml` (see `.speakeasy/workflow.yaml`). Clone `pipeshub-ai` next to this repo, then run `speakeasy run` from this repo root. It applies `.speakeasy/speakeasy-modifications-overlay.yaml` and writes `.speakeasy/out.openapi.yaml`.

To change the SDK surface, change the spec in `pipeshub-ai` (or the overlay here), then regenerate. Never patch generated code to change behaviour.

## Build and test

```bash
uv sync
uv run pytest         # tests/
uv build
```

Examples: `examples/`, run with `python` against a live instance (see `examples/README.md`).

## Release

`.github/workflows/release.yml` runs manually (`workflow_dispatch`). It runs `uv build` and `uv publish` to PyPI. It tags `v<version>` from `python.version` in `.speakeasy/gen.yaml` and creates a GitHub release. The version is bumped by Speakeasy during regeneration. CI never runs Speakeasy and does not read the spec.
