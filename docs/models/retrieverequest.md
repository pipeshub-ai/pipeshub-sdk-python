The keys are a union. For **org assistant**<br/>chat streams, send explicit lists. For **agent** chat streams, send explicit id lists,<br/>or **omit** `filters` (and `tools`) to let the service use the agent’s stored knowledge<br/>and tool configuration. A selected node that does not exist or that the caller cannot read contributes<br/>nothing; when nothing valid remains the turn searches nothing. `/search` answers 404<br/>for that; a chat turn is not failed, its search simply finds nothing.<br/>At most 200 ids may be sent in one request, counted across all keys, and every id must<br/>be a valid UUID. A key this schema does not list is refused with 400; the message names<br/>the key and lists the allowed ones. A value of the wrong type is refused with 400 too.<br/><br/>A selection that covers more than the configured number of nodes (50,000 by default),<br/>or that touches a source still being prepared for folder-level search, is refused:<br/>`/search` and the non-streaming chat routes answer 422 with the message, and a chat<br/>stream ends with an error frame (`RUN_ERROR`, or `error` on the legacy protocol)<br/>whose `code` is `selection_too_large` or `selection_not_ready` and whose `message`<br/>says what to change. No model call is made for such a turn.<br/> |
